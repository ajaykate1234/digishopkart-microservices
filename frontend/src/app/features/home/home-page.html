Separate services, one shop

DigiShopKart

The browser talks only to the gateway. Customer, product, discount, and order each have their own process and their own MySQL database. When you place an order, the order service asks the others over Feign, then stores the ids.

Open the catalog Read the terms

Customer

Name, email, mobile, and addresses. An address always belongs to one customer, so it stays in this service.

Product

Name, brand, price, category, and variants. Brand and category are columns on the product, not separate master tables.

Order

Customer id, discount id, and one line per product. The total is calculated here after Feign checks that those ids exist.

How one order moves

  1. The screen calls the gateway at /api/v1/orders.
  2. The gateway forwards the call, including the JWT, to the order service.
  3. Order service uses a Feign client to read the customer, each product, and the discount.
  4. Those services check the same JWT. A missing id comes back as 404.
  5. Order service saves the order and the line items in its own database. There is no foreign key into the other databases.
